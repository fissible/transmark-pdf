# PdfReader Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add `PdfReader`, a best-effort layout-heuristic PDF → canonical `Document` tree reader for `fissible/transmark-pdf`, closing transmark#4 (transmark-pdf#4).

**Architecture:** `PdfReader implements ReaderInterface` (from `fissible/transmark`) parses PDF bytes with `smalot/pdfparser`'s `getDataTm()` (per-text-run font size + x/y position), then reconstructs structure via layout heuristics: font-size ratio tiers classify headings vs. body text, vertical-gap-relative-to-font-size distinguishes wrapped continuation lines from real block breaks, and a same-y marker-pairing pattern detects ordered-list items. This is a best-effort reader with a hard failure mode on truly unrecoverable input (no extractable text, corrupt/encrypted PDF) — not a silent-lossy one. **Every threshold and behavior claim below was verified against real PDFs generated by this repo's own `PdfWriter`, not assumed from `smalot/pdfparser`'s documentation** — see Global Constraints for the exact validation data and why several of the originally-proposed heuristics (bullet-character detection in particular) turned out to be wrong before any code was written.

**Tech Stack:** PHP 8.2+, `smalot/pdfparser` ^2.12 (LGPLv3 — compatible with this MIT package as a Composer dependency, no relicensing obligation), PHPUnit.

## Global Constraints

**Library setup.** `Config::setDataTmFontInfoHasToBeIncluded(true)` must be set before parsing, or `getDataTm()` omits font size entirely. `Parser::parseContent(string $bytes)` (not `parseFile()`) works correctly on raw binary PDF bytes — verified identical output between the two on the same file, so `PdfReader::read()` needs no temp file, unlike `DocxReader`.

**`getDataTm()`'s tuple shape** (verified against real `PdfWriter`-generated output): `[$transformMatrix, $text, $fontId, $fontSize]`, where `$transformMatrix[4]` and `[5]` are x/y. Each entry is one physical rendered *line*, not a whole paragraph — a wrapped paragraph produces multiple entries at decreasing y with identical x.

**Failure signals, verified concretely, not assumed:**
- A PDF with zero extractable text (built via `PdfWriter` on `new Document([])`) produces `getText() === ''` and `getDataTm() === []` on every page — cleanly, no exception. `PdfReader` must check this explicitly and throw `PdfParseException`; the library will not do it for you.
- Non-PDF/corrupt content: `Parser::parseContent()` throws `Smalot\PdfParser\Exception\MissingPdfHeaderException` — verified via a real garbage-bytes call. Catch this (and, defensively, any other `\Throwable` from the parse call — encrypted PDFs and other corruption modes throw other `smalot` exception types) and wrap in `PdfParseException`; never let a third-party exception type leak from this reader's public API.
- `getDataTm()`'s known upstream coordinate-accuracy bugs on complex real-world PDFs (real GitHub issues, not theoretical) are a genuine fidelity limitation, not something this reader can self-detect. Do **not** add a "coordinates look wrong" heuristic — there is no reliable signal for it from inside this library. Document the limitation; don't chase it.

**Heading-tier thresholds, calibrated against real validated data** (a `PdfWriter`-rendered document with H1/H2/body at 24pt/18pt/12pt — dompdf's default heading scale, itself following the standard browser default heading ratios most PDF-generating tools that start from HTML/CSS will share):
- ratio (entry fontSize ÷ baseline fontSize) `>= 1.75` → Heading level 1 (validated: 24÷12 = 2.0)
- ratio `>= 1.4` → Heading level 2 (validated: 18÷12 = 1.5)
- ratio `>= 1.15` → Heading level 3 (no validated real sample at this exact tier; interpolated between the validated 1.5 and the 1.0 baseline — treat as the least-confident tier)
- else → body text
- **Baseline font size** = the statistical mode (most frequent value) of font sizes across all entries, smallest value wins ties (body text is typically both the smallest and the most common size in a normal document).

**Block-boundary (paragraph break) threshold, calibrated against real validated data:** a wrapped continuation line within the same paragraph produced a y-gap ≈ 1.19× the body font size (validated: 14.26pt gap ÷ 12pt font). A genuine block break (paragraph→heading, heading→paragraph, paragraph→list) produced gaps ≈ 1.7×–2.9× font size (validated: 34.9÷18=1.94, 30.62÷12=2.55, 26.25÷12=2.19). **Threshold: gap `> 1.5 ×` the current entry's font size signals a new block** — this sits with margin inside the validated gap between the two bands, not chosen arbitrarily.

**List detection — corrected after real validation, do not implement the originally-obvious "detect a bullet character in the text" approach:**
- **Ordered lists**: `dompdf` (and, per the PDF spec's normal text-rendering model, most PDF generators) render a numbered marker as its own separate text run, not prefixed into the item text. Verified: `"1."` at x=48.78 and `"First item"` at x=64.02 share the *exact same y*. Detection rule: two consecutive entries on the same page with `abs(entryA.y - entryB.y) < 0.01` (float-safe epsilon), `entryA.x < entryB.x`, and `preg_match('/^\d+[.)]$/', trim(entryA.text)) === 1` → merge into a single synthetic ordered-list-item entry carrying entryB's text/position/fontSize.
- **Unordered (bulleted) lists**: verified that `dompdf` renders the bullet glyph as a vector-drawn shape, **not a text run at all** — the item text (`"Bullet one"`) appears alone at the indented x with nothing preceding it on that line. There is no reliable text-based or position-only signal to distinguish a bulleted list item from any other indented content (e.g. a blockquote) without risking false positives. **v1 does not attempt unordered-list detection.**
  **Consequence, verified by running the full baseline/tier/grouping pipeline against real captured data — stronger than "loses list styling":** consecutive unordered-list items **merge into a single run-on `Paragraph`**, not separate ones. Two bullet items ("Bullet one" / "Bullet two") produced the same ≈14.26pt gap as a wrapped continuation line of one paragraph (both are single-line-height gaps below the 1.5× block-boundary threshold), and both share the same x-coordinate (indentation alone doesn't distinguish "new item" from "same paragraph, wrapped" either) — so `groupIntoBlocks()` has no signal to split them and joins the text with a space (`"Bullet one Bullet two"`). This is a genuine, unavoidable limitation of `getDataTm()`'s data for this case, not a design gap to engineer around: confirmed there is no available field that distinguishes the two situations. Task 4's test asserts this real merged-paragraph behavior, not the more benign "each item is its own paragraph" outcome an untested assumption would suggest. A future version could inspect raw content-stream vector-draw operations near a line's start to recover the boundary, but that is real scope creep beyond `getDataTm()`'s abstraction and is deliberately deferred, not attempted here.
- Never emit `NumberingRef` — matches `HtmlReader`/`MarkdownReader`. Detected ordered lists become `ListNode(ListNode::TYPE_ORDERED, [...])`/`ListItem`, never Word-style numbering.

**Explicit non-goals for v1** (state up front, do not discover mid-implementation):
- Multi-column layouts. Entries are consumed in per-page reading order (see sort below); this is correct for single-column text and will interleave columns incorrectly for multi-column layouts. Not attempted.
- Inline bold/italic recovery. `smalot`'s `Font` class has no bold/italic API; `Font::getName()` returns the raw PDF `BaseFont` string (e.g. `Arial-BoldMT`), which conventionally embeds style keywords but is unreliable against custom/subsetted font names. Deferred — cheap to add later without touching the paragraph/heading/list logic built here.
- Tables and images. Not reconstructable from `getDataTm()`'s flat text-run data without much deeper layout analysis. Deferred.
- Legal-outline numbering fidelity (the `w:isLgl` pattern that is transmark's own differentiator) cannot round-trip through PDF at all — by the time PDF text extraction sees it, the label is already-rendered plain text baked into the line, indistinguishable from any other paragraph's leading text. Task 6's integration test asserts this loss explicitly as a regression check, not a TODO.

**Reading order.** Within each page, sort entries by y descending, then x ascending as a tiebreaker (PHP's `usort()` is stable since PHP 8.0, and this project floors at 8.2, but the explicit x tiebreaker also guarantees ordered-list marker-before-item pairing regardless of raw emission order). Concatenate pages in order; no page-boundary node exists in the taxonomy (consistent with `DocxReader`/`MarkdownReader`/`HtmlReader`, none of which represent pages either).

Run `vendor/bin/phpunit` (full suite) and `composer cs` (must report zero violations) before every commit.

```php
<?php

declare(strict_types=1);

namespace Fissible\Transmark\Pdf;

use Fissible\Transmark\Contracts\ReaderInterface;
use Fissible\Transmark\Document;
use Fissible\Transmark\Nodes\Block\Paragraph;
use Fissible\Transmark\Nodes\Inline\Text;
use Fissible\Transmark\Pdf\Exception\PdfParseException;
use Smalot\PdfParser\Config;
use Smalot\PdfParser\Parser;

final class PdfReader implements ReaderInterface
{
    public function read(string $content): Document
    {
        $config = new Config();
        $config->setDataTmFontInfoHasToBeIncluded(true);

        try {
            $pdf = (new Parser([], $config))->parseContent($content);
        } catch (\Throwable $exception) {
            throw new PdfParseException(
                'Unable to parse PDF content: '.$exception->getMessage(),
                previous: $exception,
            );
        }

        $entries = $this->collectEntries($pdf);

        if ($entries === []) {
            throw new PdfParseException(
                'No extractable text was found in the PDF (it may be a scanned/image-only PDF, which is out of scope).',
            );
        }

        $blocks = [];
        foreach ($entries as $entry) {
            $blocks[] = new Paragraph([new Text($entry['text'])]);
        }

        return new Document($blocks);
    }

    /**
     * @return array<int, array{x: float, y: float, fontSize: float, text: string}>
     */
    private function collectEntries(\Smalot\PdfParser\Document $pdf): array
    {
        $entries = [];

        foreach ($pdf->getPages() as $page) {
            $pageEntries = [];

            foreach ($page->getDataTm() as $item) {
                [$tm, $text, , $fontSize] = $item;

                if (trim($text) === '') {
                    continue;
                }

                $pageEntries[] = [
                    'x' => (float) $tm[4],
                    'y' => (float) $tm[5],
                    'fontSize' => (float) $fontSize,
                    'text' => $text,
                ];
            }

            usort($pageEntries, static function (array $a, array $b): int {
                return $b['y'] <=> $a['y'] ?: $a['x'] <=> $b['x'];
            });

            array_push($entries, ...$pageEntries);
        }

        return $entries;
    }
}
```

```php
    private function baselineFontSize(array $entries): float
    {
        $counts = [];
        foreach ($entries as $entry) {
            $key = number_format($entry['fontSize'], 2);
            $counts[$key] = ($counts[$key] ?? 0) + 1;
        }

        $maxCount = max($counts);
        $candidates = array_map(
            static fn (string $key): float => (float) $key,
            array_keys($counts, $maxCount, true),
        );

        return min($candidates);
    }

    private function tierFor(float $fontSize, float $baseline): int
    {
        if ($baseline <= 0.0) {
            return 0;
        }

        $ratio = $fontSize / $baseline;

        return match (true) {
            $ratio >= 1.75 => 1,
            $ratio >= 1.4 => 2,
            $ratio >= 1.15 => 3,
            default => 0,
        };
    }

    /**
     * @param array<int, array{x: float, y: float, fontSize: float, text: string}> $entries
     * @return array<int, array{tier: int, isOrderedListItem: bool, text: string}>
     */
    private function groupIntoBlocks(array $entries, float $baseline): array
    {
        $groups = [];
        $current = null;
        $previous = null;

        foreach ($entries as $entry) {
            $tier = $this->tierFor($entry['fontSize'], $baseline);
            $isNewBlock = $current === null
                || $tier !== $current['tier']
                || ($previous !== null && ($previous['y'] - $entry['y']) > 1.5 * $entry['fontSize']);

            if ($isNewBlock) {
                if ($current !== null) {
                    $groups[] = $current;
                }
                $current = ['tier' => $tier, 'isOrderedListItem' => false, 'text' => $entry['text']];
            } else {
                $current['text'] .= ' '.$entry['text'];
            }

            $previous = $entry;
        }

        if ($current !== null) {
            $groups[] = $current;
        }

        return $groups;
    }
```

```php
     * @param array<int, array{x: float, y: float, fontSize: float, text: string}> $entries
     * @return array<int, array{x: float, y: float, fontSize: float, text: string, isOrderedListItem: bool}>
     */
    private function mergeOrderedListMarkers(array $entries): array
    {
        $merged = [];
        $count = count($entries);

        for ($i = 0; $i < $count; $i++) {
            $entry = $entries[$i];
            $next = $entries[$i + 1] ?? null;

            $isMarker = $next !== null
                && abs($entry['y'] - $next['y']) < 0.01
                && $entry['x'] < $next['x']
                && preg_match('/^\d+[.)]$/', trim($entry['text'])) === 1;

            if ($isMarker) {
                $merged[] = [...$next, 'isOrderedListItem' => true];
                $i++;
                continue;
            }

            $merged[] = [...$entry, 'isOrderedListItem' => false];
        }

        return $merged;
    }
```
